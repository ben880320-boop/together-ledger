# Together Ledger v1.2.0：離線 APK 建置指南

## 交付狀態

本建置包包含 Together Ledger v1.2.0 的完整程式碼、Expo Android 設定、GitHub Actions workflow、測試與建置文件。它不包含尚未成功產出的 APK；本 sandbox 已安裝 Android SDK、Gradle 與 Java 17 並嘗試本機建置，但 Gradle daemon 在 Android manifest／AAPT 處理期間被環境終止，因此不把未取得的檔案宣稱為 APK 交付。

這個方案不依賴 Expo EAS，也不需要 Expo token。使用者可以在自己的 Android Studio／Android SDK 環境中建置，或將此專案推送到自己的 GitHub repository 後執行內含的 Actions workflow。

## 建置環境

| 元件 | 版本或要求 |
|---|---|
| Node.js | 22.x |
| pnpm | 11.21.0 |
| Java | JDK 17 |
| Android platform | Android 36 |
| Android Build Tools | 36.0.0 |
| Android NDK | 27.1.12297006 |
| 網路 | 首次安裝依賴與 Gradle 套件時需要 |

Android 36、Build Tools 36 與 NDK 27.1 是 Expo SDK 54 prebuild 後由目前專案實際使用的版本。請不要只安裝 Android 35；若使用 Android Studio，請在 SDK Manager 中一併安裝上述元件。

## 方法一：Android Studio 建置

解壓縮建置包後，使用 Android Studio 開啟 `mobile/android`，不是開啟整個 repository。第一次開啟時等待 Gradle Sync 完成，並在 Android Studio 的 Gradle JDK 設定選擇 JDK 17。確認 SDK Manager 已安裝 Android 36、Build Tools 36.0.0 與 NDK 27.1.12297006。

同步完成後，先在 Android Studio 的 **Build Variants** 將 `app` 設為 `release`，再選擇 **Build → Generate App Bundles or APKs → Generate APKs**。請使用 release 變體；debug 變體不會內嵌 JavaScript bundle，直接安裝後會要求連線到 Metro，便會出現 `Unable to load script`。建置成功後，APK 位於：

```text
mobile/android/app/build/outputs/apk/release/app-release.apk
```

這是可離線啟動的 release APK；目前 workflow 使用內建 debug keystore 簽署，適合測試安裝，不代表正式商店簽署版本。安裝到手機前，若 Android 系統要求，請允許目前使用的檔案管理器或瀏覽器安裝未知來源應用程式。

## 方法二：命令列 Gradle 建置

在已安裝 Node.js、pnpm、JDK 17 與 Android SDK 的環境中執行：

```bash
cd together-ledger/mobile
pnpm install --frozen-lockfile
pnpm run prebuild:android
cd android
chmod +x ./gradlew
./gradlew --no-daemon --stacktrace assembleRelease
```

成功輸出後，檔案位於：

```text
mobile/android/app/build/outputs/apk/release/app-release.apk
```

若環境沒有自動找到 Android SDK，請先設定 `ANDROID_HOME` 與 `ANDROID_SDK_ROOT` 指向 SDK 根目錄，並將 SDK 的 `platform-tools` 放入 `PATH`。本交付包保留已由 Expo prebuild 生成的 `mobile/android` 原生專案，並排除 `build`、`.gradle` 與環境專屬暫存檔，因此可以在安裝 JavaScript 依賴後直接用 Android Studio 開啟。若使用者從 Git repository 重新 checkout、或刪除了原生目錄，再執行 `pnpm run prebuild:android` 即可重建它；`mobile/android` 在 repository 中仍維持被忽略的既有規則。

## 方法三：GitHub Actions 建置

將專案內容推送到自己的 GitHub repository，確認 `main` 分支包含最新的 `.github/workflows/android-apk.yml`，然後在 repository 的 **Actions** 頁面選擇 **Build Android APK**，按 **Run workflow**。workflow 會使用 Ubuntu 24.04、Node 22、pnpm 11.21.0、Java 17、Android 36、Build Tools 36 與 NDK 27.1，執行 Expo prebuild 及 Gradle `assembleRelease`，把 JavaScript bundle 內嵌至 APK。

成功後，在該次 workflow run 的 **Artifacts** 區下載名稱類似 `together-ledger-1.2.0-release-apk` 的 artifact。解壓縮後即可取得 `app-release.apk`。artifact 預設保留 14 天；請在期限前下載保存。

此 workflow 不會讀取 Expo token，也不需要 EAS 登入。它只使用 workflow 內已設定的公開建置環境變數，應用程式的 OAuth 與 API 仍連到專案目前設定的 Together Ledger 服務端點。

## 安裝與基本驗證

將 `app-release.apk` 傳送到 Android 手機後點擊安裝，或在已啟用 USB 偵錯的裝置執行：

```bash
adb install -r mobile/android/app/build/outputs/apk/release/app-release.apk
```

安裝後請依序確認：第一次開啟先顯示登入／註冊頁；登入後可建立真正空白的新帳本；帳本內只有一個可正常運作的個人設定登出入口；出遊規劃可以使用原生日期選擇器建立日期範圍；個人設定中的海洋、星空、森林與薰衣草等主題，以及卡片／導覽列樣式可套用；分類與支付方式可搜尋、編輯、排序、停用與恢復；編輯或刪除交易及登出操作會出現一致的確認流程。

## 建置包與版本確認

建置前可在 `mobile/package.json` 確認版本為 `1.2.0`。建置後可使用下列指令產生檔案雜湊，方便傳輸後核對：

```bash
sha256sum mobile/android/app/build/outputs/apk/release/app-release.apk
stat -c '%s bytes' mobile/android/app/build/outputs/apk/release/app-release.apk
```

若 GitHub Actions 建置失敗，請先查看 workflow log 中的 **Install Android SDK components**、**Generate native Android project** 與 **Build standalone release APK with embedded JavaScript bundle** 三個步驟；若手機出現 `Unable to load script`，通常是下載或安裝了舊的 debug artifact，請改下載 `release-apk` artifact。若是 repository 權限或 404，請先確認 repository 已存在、目前帳號有寫入權限，且最新 workflow 檔案已推送到 `main` 分支。
