# v1.3.7 後續迭代建議

本文件將 v1.3.7 後最值得投入的工作依風險與使用者影響排序。建議以可驗收的交付條件取代僅列出功能名稱，避免跨 Android、Web／PWA 與 tRPC 層出現「已完成但未同步」的情況。

| 優先級 | 建議 | 可執行範圍 | 完成驗收條件 |
| --- | --- | --- | --- |
| P0 | Pull Request 品質閘門與 main 保護 | 新增僅於 PR 執行的 GitHub Actions 工作流程，分別執行 `pnpm exec tsc --noEmit`、`pnpm test`、`pnpm exec tsx mobile/scripts/verify-core-flows.mjs` 與 `pnpm build`。再依 `BRANCH_PROTECTION.md` 開啟 required checks、至少一位核准、對話解決與禁止直接推送。 | 任一檢查失敗時無法合併；固定簽章 APK 僅在合併至 `main` 後發行，不會從未合併 PR 建立 Release。 |
| P0 | 交易與儲蓄桶的並發衝突覆蓋稽核 | 逐一盤點新增、編輯、刪除交易、預算、儲蓄桶與帳本設定的 tRPC procedure，統一帶入 `version` 或 `updatedAt` 比對。前端對 `409 Conflict` 顯示「重新整理後再編輯」與受控的「覆蓋」選項，並保留衝突對象與時間。 | 兩個模擬使用者同時編輯同一筆資料時，舊版本不能靜默覆蓋新版本；權限不足與版本衝突各自回傳可辨識錯誤碼並有 Vitest 覆蓋。 |
| P0 | 金額與分攤不變量測試 | 將所有金額傳輸、資料庫與計算統一為整數分（或等價的精準 Decimal），為平均分攤、自訂分攤、退款與負數調整建立 property-based／表格化測試。餘額的分配順序應明確且可重現。 | 任意交易的「各成員分攤總和」必等於交易總金額；例如 100 元三人分攤可驗證為 33.34、33.33、33.33，且總覽、月曆、分析與預算在編輯／刪除後同步一致。 |
| P1 | SSE 同步韌性與離線佇列 | 對 EventSource 增加指數退避、抖動、連續失敗上限、可見的重連狀態與手動重試；將離線可安全重送的意圖寫入具 schema version 的本機佇列，重連後逐筆以冪等鍵送出。 | 在斷網、背景切換、伺服器重啟與連續重連情境中，草稿不遺失、不重複建立交易；狀態中心可顯示最後同步時間、失敗原因與重試入口。 |
| P1 | 收據處理效能與隱私邊界 | 將收據掃描改為背景任務：先本機縮圖／壓縮、顯示可取消進度，再以使用者確認後的結構化欄位建立草稿。保存圖片時採 S3 受控存取、最小化保留期與遮蔽式錯誤紀錄，避免收據影像出現在一般日誌。 | 中斷、逾時與解析失敗均有可重試入口；使用者可在送出前更正商家、日期、金額與分類；影像 URL 不直接公開且不被事件紀錄輸出。 |
| P1 | 行動端與清單效能預算 | 針對月曆、近期收支、活動日誌與圖示選擇器採視窗化／分頁載入，量測低階 Android 的首屏、切換分頁與長清單捲動。Android 採 Hermes、release bundle 分析與圖示資料延遲載入；Web 端以 Vite chunk 分析確認不把非必要功能併入首屏。 | 設定明確效能預算並在 CI 保留產物大小比較；含大量歷史交易的月曆與列表不會無限制拉長，首次互動不被長任務阻塞。 |
| P2 | 月曆與交易操作體驗 | 在交易清單加入具明確復原能力的左滑編輯／刪除、篩選條件記憶與「本週／本月／上月」快速切換；月曆採虛擬化月份與手勢切換，並確保鍵盤開啟時焦點欄位可見。 | 高風險刪除仍有二次確認；取消手勢不會誤刪；Web、PWA 與 Android 的篩選語義與日期邊界一致。 |
| P2 | 金流可觀測性與例外監控 | 為新增／編輯／刪除、分攤計算、SSE 同步、收據解析與 APK 更新檢查建立結構化 audit event；正式環境串接錯誤追蹤服務，將例外以匿名帳本 ID、版本、平台、錯誤碼與 correlation ID 關聯。 | 可由單一 correlation ID 追查一次失敗；敏感欄位（邀請碼、電子信箱、金額明細、影像 URL）不進入監控 payload；同步失敗與金額不變量錯誤有可行動告警。 |

## 建議執行順序

先完成 P0 的 PR 品質閘門、並發衝突稽核與金額不變量測試，因為這三項直接降低錯誤發布、資料覆蓋與帳務錯誤的風險。接著以 P1 強化離線同步、收據處理與效能預算，讓日常記帳在網路波動與資料量增加時仍保持可預期。最後進行 P2 的操作體驗與正式監控，將使用體驗回饋與真實故障資料帶回下一輪產品決策。
