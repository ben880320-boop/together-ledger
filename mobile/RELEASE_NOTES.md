## Together Ledger v1.3.13

### Firebase 電子郵件帳號安全

- Android App、Web 與 PWA 統一採用 Firebase Authentication Email／Password：新帳號註冊後必須先完成 Email 驗證，登入頁提供重寄驗證信與不揭露帳號存在與否的忘記／重設密碼入口。
- 既有本機帳密使用者可從個人設定以相同、已驗證的電子信箱綁定 Firebase；此過程不變更既有使用者 ID、帳本成員資格、交易或設定。
- Firebase 登入使用一小時短效 app session，JWT 以 session version 集中驗證；綁定時會撤銷舊 session，Android 可在 Firebase 已驗證身份有效時安全自動換發。
- Firebase 已綁定帳戶的刪除流程要求重新輸入 Firebase 密碼，伺服器再驗證五分鐘內的 ID Token、UID 與相同電子信箱後移除 app 與 Firebase identity。

### 發布與安全性

- Android 版升級為 `versionName=1.3.13`、`versionCode=36`。APK 建置僅注入 Firebase client 公開設定；服務帳號憑證保持在伺服器端，不會寫入 APK。

## Together Ledger v1.3.3

### 儲蓄桶額外存入與收支類型保護

- Android App、網頁版與 PWA 的儲蓄桶皆可由使用者在有可用餘額時執行「額外存入」。金額以整數分保存，會從該桶已設定的扣款支付方式轉存，並立即同步更新目標進度與三端畫面。
- 每次額外存入都會建立不可編輯、不可刪除的正式轉存與分配稽核紀錄，會清楚標示為「手動額外存入」；自動每月分配則維持原有的「自動分配」來源標示。
- 額外存入會檢查帳本權限、支付方式可用餘額與儲蓄桶版本。若餘額不足或其他成員已更新同一目標，畫面會保留輸入並提供明確錯誤或重新整理入口，不會靜默覆寫。
- 網頁一般「新增／編輯收支」現在只提供收入與支出。轉帳僅能由受保護的儲蓄桶自動／手動轉存流程建立，避免一般收支誤建系統轉存資料。

## Together Ledger v1.3.0

### 儲蓄桶與正式資金轉存

- Android App、網頁版與 PWA 的「規劃」頁新增儲蓄桶。可不限數量建立買車基金、旅行、房屋頭期款或自訂目標，並設定目標金額、每月固定分配額度、扣款支付方式、每月分配日期與優先順序。
- 系統每日檢查到期桶後，會依優先順序以正式 `transfer` 交易記錄轉存；若可用餘額不足，將部分分配並記錄不足金額。轉存不列入收入、支出或消費分析。

### 共同編輯保護

- 儲蓄桶更新與暫停均使用版本比對。若其他成員先完成異動，畫面會要求重新整理後再編輯，不會靜默覆寫對方設定。
- 正在使用的扣款支付方式不可被隱藏或刪除，避免排程失去有效資金來源。
