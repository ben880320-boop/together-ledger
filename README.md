# 共帳 Together Ledger

**Together Ledger（共帳）** 是以「兩人共同生活」為核心的共享記帳服務。使用者可以透過 Android App 或網頁版，以同一組電子信箱與密碼登入同一份帳本資料；建立帳本、加入共同帳本、記錄收支、分攤款項、管理預算及檢視結算，都會同步反映於兩個平台。

> 本專案不會在新帳號或新帳本中建立範例交易、預設帳本或虛構資料。登入後，使用者會先進入「我的帳本」，再自行建立空白帳本或輸入邀請碼加入既有帳本。

| 平台 | 適用情境 | 使用入口 |
| --- | --- | --- |
| Android App | 日常收支、新增交易、相機／相簿掃描收據及行動裝置更新 | [GitHub Releases](https://github.com/ben880320-boop/together-ledger/releases) |
| 網頁版／PWA | 電腦、iOS 或未安裝 App 的使用者；可使用相同帳號、帳本與核心工作區，並加入裝置主畫面 | [Together Ledger 網頁版](https://togetherapp-hdbmsjkf.manus.space) |

## 產品流程

登入成功後，App 與網頁版都會先顯示 **我的帳本**。在此頁面可以搜尋已加入的帳本、檢視同步狀態、建立新的共同帳本，或以邀請碼加入另一個帳本。帳本設定產生的 QR Code 與分享連結採用 HTTPS 邀請頁：已安裝 Android App 時會優先開啟 App；未安裝 App、使用 iOS 或電腦時，則可在網頁／PWA 登入後安全加入。選擇帳本後，系統會開啟帳本工作區；使用者可以透過總覽、月曆、分析、規劃與設定切換主要功能，收支與個人設定則保留為清楚的工具入口。

| 流程 | 說明 |
| --- | --- |
| 1. 註冊或登入 | 使用電子信箱與密碼建立帳號；新帳號必須先完成 Email 驗證，Android 與網頁版使用同一帳號。 |
| 2. 建立或加入帳本 | 建立空白共同帳本時可選擇圖示或「無」；可輸入邀請碼，也可掃描 HTTPS QR Code／開啟邀請連結，在 App、Web 或 PWA 上登入後加入。 |
| 3. 記錄共同收支 | 選擇付款人、分類、支付方式、日期及分攤規則；可新增、編輯或刪除。 |
| 4. 查看生活財務 | 透過總覽、月曆與分析掌握近期收支、成員支付、分類支出及結算狀態；分類金額與比例集中於分析頁。 |
| 5. 規劃與管理 | 設定分類預算、固定收支、出遊規劃與儲蓄桶，並在帳本設定中管理成員、分類、支付方式及日誌。 |

## 網頁版與 Android App 的資料互通

兩個平台均連到同一個帳號與帳本服務。v1.3.5 起，新增、編輯或移除收支，以及預算、分類、支付方式、儲蓄桶、帳本設定與成員異動，會以可重連的 **SSE 帳本事件流** 通知另一端重新取得相關資料；事件只傳遞帳本游標與異動類型，不會傳送金額、明細或收據內容。若串流暫時不可用，現有的重新整理與離線快照仍可使用。工作區會採安全快取、節流輪詢備援與 memoized 衍生資料，減少重複讀取與重繪；Web／PWA 會集中顯示連線狀態、最後同步時間與重新整理入口。同步失敗時會保留原因並提供重新嘗試的入口。

## 電子郵件帳號安全與既有帳戶遷移

v1.3.13 起，新使用者以 **Firebase Authentication Email／Password** 建立帳號。註冊後系統會寄出驗證信；完成驗證後，才能以相同帳號登入 Android、Web 與 PWA。登入頁提供重新寄送驗證信與「忘記密碼」入口；忘記密碼一律顯示不揭露帳號存在與否的通用完成訊息。Firebase 密碼重設完成後，使用者應以新密碼重新登入。

既有的本機帳密使用者不會因升級失去帳本、成員資格、交易或設定。請先以既有帳密登入，再從「個人設定 → 帳戶安全」用**完全相同且已驗證的電子信箱**完成 Firebase 綁定。綁定完成時，伺服器保留原有使用者 ID 和所有帳本關聯，並撤銷舊 app session；新登入使用一小時短效 app session，Android 在 Firebase 已驗證身份仍有效時會自動換發。Firebase 已綁定帳戶的刪除操作必須以 Firebase 密碼重新驗證，且伺服器會驗證近期 ID Token、UID 與電子信箱一致後再移除身份資料。

> **管理員部署檢查：** Firebase Console 的 Authentication → Settings → Authorized domains 必須加入正式網站 `togetherapp-hdbmsjkf.manus.space`，才可讓驗證／重設信的 Firebase Hosted action page 完成後安全返回網站登入頁。GitHub Actions 另需設定僅供 Android client 使用的 `EXPO_PUBLIC_FIREBASE_API_KEY`、`EXPO_PUBLIC_FIREBASE_AUTH_DOMAIN`、`EXPO_PUBLIC_FIREBASE_PROJECT_ID` 與 `EXPO_PUBLIC_FIREBASE_APP_ID` secrets；服務帳號 JSON 絕不可放進 APK 或 GitHub Actions client 環境。

## 跨平台邀請與每月結算快照

帳本設定的「邀請成員」會產生可分享的 HTTPS 連結與 QR Code。Android 上若已安裝 App，邀請頁會優先嘗試開啟原生 App；未安裝 App 時會保留於網頁邀請頁，使用者可以先閱讀加入說明，再選擇登入／註冊後加入或前往 Android 下載頁。無論入口為何，加入帳本時都會由伺服器驗證邀請碼、登入身分與帳本存取權；請勿在公開場所張貼邀請連結或 QR Code。

結算採用 **每月快照**：成員先針對當月未結清差額提出結算，另一位成員確認後才會鎖定該月份的結算紀錄。已鎖定月份不可新增、編輯或刪除會影響該月金額的收支；若發現需要修正，帳本管理員必須先明確重新開啟該月結算，再完成修正並重新提出確認。每個帳本每個月份只有一筆具版本保護的結算快照，因此多人同時操作時不會靜默覆寫對方的結算狀態。

網頁版依 Android 的行動資訊架構提供「我的帳本」首頁、總覽、月曆、分析、規劃、帳本設定與個人設定。由於裝置能力不同，Android App 提供系統安裝引導與相機流程；網頁則提供檔案選取及下載行為。通知與預算門檻提醒目前暫停。

## 儲蓄桶與每月資金分配

在帳本的「規劃」頁，可建立不限數量的儲蓄桶，例如買車基金、日本旅遊、房屋頭期款或電腦基金。每個桶必須指定一個啟用中的扣款支付方式，並可各自設定目標金額、每月固定分配金額、每月 1 至 28 日的分配日期與優先順序。每日排程會處理已到期且尚未處理的桶；同月份的重試以冪等鍵保護，不會重複轉存。

分配時會依優先順序計算當下帳本可用餘額。若金額不足，較高優先順序的桶可獲得部分分配，系統會在分配歷程保存預定、已分配與不足金額。使用者也可在有餘裕時，從同一張儲蓄桶卡片執行「額外存入」；金額會使用該桶的扣款支付方式，先驗證可用餘額與桶版本，並立即同步更新進度。每一筆自動或手動成功分配都會建立正式 `transfer` 交易與唯讀稽核紀錄，歷程會標示「自動分配」或「手動額外存入」；不計入收入、支出、月曆消費標記或分析圓餅圖。一般新增／編輯收支只提供收入與支出，不能手動建立轉帳。儲蓄桶更新與暫停使用版本比對，遇到共同編輯衝突時會提示重新整理後再編輯。首次達標會顯示慶祝提示；可封存／隱藏已達標目標以停止後續分配，而不會刪除既有交易與稽核歷程，並可重新顯示管理。

開啟中的新增或編輯表單會保存自己的輸入草稿。背景同步只更新已提交資料，不會清除或重設尚未儲存的文字、日期、金額與選項。

## 將網頁版加入主畫面（PWA）

Together Ledger 網頁版可安裝為 PWA，安裝後會以獨立視窗開啟，並快取公開介面與靜態資源，讓網路暫時中斷時仍可開啟應用程式與閱讀最近成功同步的帳本快照。為保護帳務資料，Service Worker **不會快取**登入、tRPC 或帳本 API 回應；離線時不可新增、修改或刪除交易，恢復連線後請使用既有同步／重試入口。

| 裝置 | 安裝方式 |
| --- | --- |
| iPhone／iPad | 以 **Safari** 開啟網頁版，按「分享」後選擇「加入主畫面」，再於主畫面開啟共帳。 |
| Android 瀏覽器 | 於公開首頁按「開始使用網頁版」後依瀏覽器提示安裝，或從瀏覽器選單選擇「安裝應用程式」。 |
| 電腦瀏覽器 | 使用網址列或瀏覽器選單提供的安裝圖示；若未顯示，仍可直接用網頁版。 |

當 PWA 偵測到新版時，會先檢查是否仍有開啟中的表單草稿。若有未提交輸入，系統會保留草稿並要求先儲存或關閉表單，避免新版重新載入造成遺失；完成後再選擇重新載入以套用新版本。

## 下載、安裝與更新 Android App

目前 Android App 版本為 **1.3.13**（versionCode 36）。此版本以 Firebase Authentication 統一 Android、Web 與 PWA 的 Email／Password 註冊、驗證、重寄驗證信、忘記／重設密碼、既有帳戶同信箱綁定與安全刪除流程，並加入短效 app session 與版本撤銷保護。請僅從本專案的 [GitHub Releases](https://github.com/ben880320-boop/together-ledger/releases) 下載官方 APK，並以 Release 頁面附列的 SHA-256 檢查碼確認檔案來源。

| 步驟 | 操作 |
| --- | --- |
| 1 | 於 Android 裝置開啟 [最新 Release](https://github.com/ben880320-boop/together-ledger/releases/latest)，下載 `together-ledger` APK。 |
| 2 | 開啟已下載的檔案，依 Android 系統提示允許目前瀏覽器或檔案管理器安裝應用程式。 |
| 3 | 完成安裝後，新帳號請以完成 Email 驗證的電子信箱與密碼登入；既有帳戶可先用舊帳密登入，再於個人設定綁定相同信箱，不需要重新建立帳本。 |
| 4 | App 偵測到官方新版時，可先查看目前／最新版本、下載進度、官方來源、SHA-256 校驗提示與安裝診斷，再依提示下載及安裝。 |

> 安裝 APK 的系統權限只用於完成你主動發起的更新安裝。請勿從非官方網站、聊天訊息或未知來源下載同名 APK。

> **固定簽章更新：** v1.3.3 起，官方 APK 均使用同一組受保護簽章，可由已安裝的官方版本直接覆蓋更新；若裝置仍保有更早期、不同簽章的歷史安裝且顯示「無法更新」或「套件衝突」，請先移除舊版，再安裝 v1.3.13 官方 APK 一次。移除 App 不會刪除伺服器上的帳本資料。

## 隱私與資料安全

通知、推播裝置註冊與預算門檻提醒目前已暫時停用，Android App 不會要求通知權限。收據掃描只會在使用者主動選擇相機、相簿或檔案時存取該項裝置能力。

Android 的「協助回報技術錯誤」預設為關閉。只有使用者在「我的帳本 → 個人設定 → 帳戶與支援」閱讀說明並明確開啟後，App 才會傳送平台、App 版本、錯誤代碼、技術訊息及已遮蔽的堆疊資訊。此診斷流程不會傳送帳本、收支、金額、邀請碼、帳號、電子信箱、密碼、憑證或收據圖片，且可隨時關閉；伺服器在寫入前會再次驗證使用者同意狀態並遮蔽敏感字串。

帳本、成員、交易與操作日誌只用於共同記帳與結算流程。邀請碼可讓他人申請加入帳本，因此不應公開張貼；同樣地，請勿在公開 Issue、截圖或討論串中附上電子信箱、密碼或交易內容。
